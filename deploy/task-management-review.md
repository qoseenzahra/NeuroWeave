# 任务管理分支审阅说明

开发分支：`codex/task-management-pipeline-ui`；合并目标：`main`。本说明描述分支最终行为，具体版本的验证结果记录在 PR 和对应提交的 CI 中。

## 用户界面与任务入口

- 任务管理统一显示对话规划和 Pipeline 创建的任务，支持搜索、来源/运行状态筛选、分页以及任务配置和运行历史。创建后沿用输入绑定、参数审核、预检、确认、日志及产物查看流程。
- Pipeline 独立于 Skill / Method 侧栏。“从 Pipeline 创建任务”先选择版本和本次输入、输出目录，创建后打开任务配置；当前对话的上下文保持独立。
- 输出目录使用路径选择窗口，支持父级跳转和复用已登记目录；数据集选择入口、编排器面板开关和侧栏滚动边界已整理。
- 内置和已发布 Pipeline 的详情为可选择节点的只读画布，参数展示与草稿共用方法契约；可创建独立副本编辑。草稿和用户已发布 Pipeline 提供删除与恢复，内置 Pipeline 保持只读。

详见 [任务管理](task-management.md)、[方法参数与预设](pipeline-parameters-and-presets.md)、[发布删除](published-pipeline-deletion.md)。

## 定义与参考资料

当前目录包含 105 个规范 Skill、328 个 Method、24 个内置 Pipeline。Skill 由 `skill.json` 加载，执行契约由 Method 和 Runner 维护；需要补充背景的 Skill 在 `references/` 中显式登记资料并按需读取。通用政策只在平台提示词维护，Skill 保存自身有选择价值的指导。

移除旧别名、Markdown DAG 解析及未被当前执行链使用的清单。dcm2niix 的 7 条 Pipeline 按完整执行定义去重为 3 条；三者使用同一方法，差异在固定参数和公开参数的约束，不能据此声称有三种不同转换实现。

详见 [兼容层清理](skill-compatibility-cleanup.md)、[参考资料](skill-references.md)、[专属指导](skill-guidance.md)。

## 合并前代码清理

1. 删除应用入口已不再引用的 `SkillList`、`SkillCard`、`SkillSearch`，移除仅供这些组件使用的双语字段和旧组件测试；`App` 直接使用当前 `LibraryPanel`。消息输入框的清空已选 Skill、会话搜索的清空搜索等共享功能保留。
2. 详情窗口只记录选择身份，查询缓存负责定义加载、版本及语言变化。移除“按钮先读取、Effect 再读取”的双重请求；版本按钮同样只选择版本。
3. 统一 Method 契约查询与请求取消。统一 Pipeline 缓存失效规则，发布、归档、删除和恢复后刷新相应详情、来源、版本和迁移状态。
4. 后端一次查询读取指定版本及生命周期状态；创建任务使用该版本返回的归档状态，移除扫描整个资源库的重复检查。补充快照边界、删除重试和恢复后保留修订号的注释。

删除的旧前端组件没有当前应用依赖；保留正在使用的模型、Runner、输入绑定及运行监控。通用 UI 组件库不因某个页面暂未引用而批量删除。

## 数据与验证边界

发布版本内容、版本归档状态和整个 Pipeline 的删除状态分别存储。回收站恢复全部版本，但保留各版本此前的归档状态；现有任务使用创建时的执行快照。草稿与发布版本独立保存。

旧 Skill 别名和已删除的重复 Pipeline ID 不再提供兼容解析。部署前应检查目标数据库是否仍引用这些已退役 ID；历史开发测试条目的清理范围见兼容层清理记录，不能把它当作任意删除研究数据的指令。

本分支验证使用隔离数据库和合成文件。检查包含完整后端测试、发布与能力树检查、前端 lint、测试和构建；新增回归验证指定版本的归档状态、并发消费者共享请求、请求取消和跨视图缓存失效。科学软件的真实数据验证以对应 Method 的运行证据为准。
