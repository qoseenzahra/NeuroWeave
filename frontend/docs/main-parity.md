## 已补齐

| 范围 | 行为 |
|---|---|
| 全局上下文 | 顶部、数据集侧栏、流程卡统一采用流程数据集；锁定/确认/请求处理中禁止替换。更换时提交 expected_revision 并采用服务端返回状态。 |
| 历史恢复 | 恢复模式、技能、数据集和输出目录；兼容旧消息 metadata。后台刷新不会覆盖用户打开对话后作出的选择。 |
| 消息一致性 | 通过读取代次区分过期请求和发送完成后的权威快照，消除本地消息与持久化消息重复；不按文本误删重复提问。 |

| 输出目录 | 登记、选择、改名、取消关联；切换根目录同时更新对话与当前流程。权限不足的目录不可选；保留后端最终校验。 |
| 数据集文件 | 独立只读浏览、分页、检查、文本预览；不展示移动、删除、覆盖、重命名等写操作。 |
| 服务器目录面板 | 可点击面包屑、正确返回相对根、绝对路径跳转、完整路径复制、拖动/键盘调宽、滚动续页。 |
| 新建文件夹 | 选择输出目录时即可创建；显示准确路径并确认；成功后进入目录，可直接登记；成功提示约 2.5 秒收起，审计记录保留。 |
| 模型工具时间线 | 识别 dataset/output 新工具名称，展示作用域和执行结果；失败信息保留。 |
| 流程请求 | 共享查询缓存、最多两个并发流程读取、拒绝旧 revision 覆盖新状态；dry-run 冲突采用服务端当前流程。 |
| 执行设置 | 等草稿加载完成后初始化；离开时保留保存；资源校验同时约束启动按钮。无 Slurm 时保留合法分区默认值，local 启动可正常保存草稿。 |
| 监控操作 | 恢复监控采用服务端返回状态；取消、重试、恢复错误可见；操作处理中禁止重复请求；重新打开获取最新运行。 |
| 任务输出 | 相对输出目录仍可查看/复制完整服务器路径；输出文件保留分页和筛选。 |
| 布局及提示 | 保留新主题和侧栏；窄屏侧栏覆盖展示，顶部可换行；修复方法说明空 key；显示 FastAPI 字段级错误。 |

## 后续逐项核查修复（2026-09-21）

先前对齐记录覆盖主要链路，不代表逐项一致。本次修复核查中确认的六项差异：

- 恢复监控仅供 queued/running/cancel_requested 的 Slurm 任务使用，与后端契约一致。
- failed/cancelled 任务增加“重试所有未完成步骤”，调用已有 retry API，step_ids=[] 由后端确定范围并验证已完成输出；操作进行中禁止重复提交。
- 启动同时要求最终确认、dry-run 有效、execution_enabled 且无活动任务。运行信息/草稿加载及参数保存、提交期间禁用启动；结束后显示“再次运行”。参数保存包含在同一次启动 mutation 内。
- Skill 卡片采用 execution_state、ready_runner_count 和 runtime_reasons，显示可运行、待配置环境、可规划及缺失依赖；没有运行证据的旧响应显示“运行状态未确认”。
- 任务模式中无流程及无能力建议的回答，根据已有元数据提示需要补充信息或无需生成流程；普通对话、已生成流程不显示该提示。
- 监控及输出分页在结果缩减时保存修正后的页码，结果增加时不跳回过期页码。

按用户指定，演示模式提示及存储面板的前端版本展示保持原样。没有改动 BackendStatusDot.tsx、StoragePanel.tsx，也未注入新的版本环境变量。

新增五项自动测试（总计 28 项）覆盖恢复/重试状态矩阵、批量重试 API、Skill 运行证据、对话提示、启动状态矩阵。另使用真实前端组件和完全隔离的合成 API 响应，在浏览器验证：24→9→24 个任务后保持第 2 页；批量重试发送空 step_ids；活动 Slurm 恢复监控；执行未启用时无启动入口；参数保存后按 CPU=6 提交一次并禁用按钮，返回 queued 后隐藏启动入口；Skill 状态及原因可见。浏览器无警告或错误。

本次不提交真实 Slurm/GPU 任务，服务器只更新 3001 静态前端；发布前比对现有清单、内容哈希及本地基线，保留旧发布和备份。

## 方案流程收起（2026-09-21）
